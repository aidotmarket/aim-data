### DuckDB-to-logical-schema dispatch table

This is the proposed exhaustive dispatch: resolve DuckDB aliases to a base type first, match the rows below, and reject everything else. Later-version names are explicitly rejected where the installed 0.9.2 runtime cannot produce them. The table is an implementation decision, not a claim that current AIM Data maps these types. Upstream type inventory was consulted at [DuckDB types](https://duckdb.org/docs/current/sql/data_types/overview); runtime support must be tested against the repository pin, not that newer documentation.

`{}` means no parameters, not five null-valued parameter keys. A field descriptor is `[NFC(name), tag, nullable, parameters]`. Use the declared logical schema's nullability; do not infer non-nullability from sampled rows. An undeclared nullable state requires local confirmation, not a guessed signed descriptor. Allowed parameter names and recursive object shapes follow `BE:app/schemas/listing_enrichment.py:68–80,119–154,306–322`.

| DuckDB resolved type / aliases | logical_type_tag | type_parameters and admission |
|---|---|---|
| BOOLEAN / BOOL / LOGICAL | `boolean` | `{}`; actual boolean, never integer coercion |
| TINYINT / INT1; SMALLINT / INT2 / SHORT; INTEGER / INT / INT4 / SIGNED; BIGINT / INT8 / LONG; HUGEINT | `signed_integer` | `{}`; exact minimal base-10 value string, no float intermediary |
| UTINYINT, USMALLINT, UINTEGER, UBIGINT; UHUGEINT if a future runtime supports it | `signed_integer` | `{}`; nonnegative values are represented exactly as integer strings, never wrapped into a signed machine word; future unsupported physical types fail |
| DECIMAL(p,s) / NUMERIC(p,s) | `decimal` | `{"precision":p,"scale":s}`; exact decimal parse, finite, no rounding; normalize negative zero to `0`, strip insignificant fractional zeros, no exponent; validate declared precision/scale before normalization |
| FLOAT / REAL / FLOAT4; DOUBLE / DOUBLE PRECISION / FLOAT8 | **unsupported** | No approved binary-float tag; reject even finite values. Seller must supply a separately declared lossless decimal source/schema; do not cast behind the scenes. NaN/infinity always fail |
| VARCHAR / CHAR / BPCHAR / TEXT / STRING | `string` | `{}`; strict UTF-8, NFC, preserve whitespace; invalid Unicode fails |
| DATE | `date` | `{}`; finite YYYY-MM-DD only, reject infinities/out-of-range dates |
| TIMESTAMP / DATETIME, TIMESTAMP_S, TIMESTAMP_MS, TIMESTAMP_NS | `timestamp` | `{"timestamp_precision":6/0/3/9}` respectively, but admit only with an explicit unambiguous source UTC/offset declaration. Naive local times fail; do not assume workstation timezone. Preserve nanoseconds outside Python microsecond datetime conversions |
| TIMESTAMP WITH TIME ZONE / TIMESTAMPTZ | `timestamp` | `{"timestamp_precision":6}` for pinned runtime; normalize exact instant to UTC; no silent rounding or infinite values |
| BLOB / BYTEA / BINARY / VARBINARY | `binary` | `{}`; unpadded base64url exact bytes for full commitment; any selected row containing binary is ineligible, including nested binary |
| LIST / T[] | `array` | `{"element_type":{"type":tag,"type_parameters":parameters}}`; ordered, homogeneous declared logical type, recurse; null elements remain null |
| STRUCT with declared named members | `object` | `{"object_fields":[{"name":name,"type":tag,"nullable":bool,"type_parameters":parameters},...]}`; NFC unique member names sorted by UTF-8 bytes, recurse, reject unknown members |
| ARRAY / T[N] in newer runtimes | **unsupported in this build** | Fixed-length semantics are not represented by a declared length parameter in Chunk 0; no silent collapse to LIST |
| MAP, UNION | **unsupported** | Dynamic key sets/discriminants lack this profile's exact descriptor; no conversion to strings/objects |
| ENUM, UUID | **unsupported** | No implicit loss of enum/UUID semantics by string cast; a seller-declared string source is a distinct explicit schema |
| JSON logical/extension type | **unsupported as an opaque DuckDB cell** | JSON input files are supported through the presence-preserving parser with a declared scalar/array/object schema; never hash a JSON text cell as an inferred object |
| TIME, TIME WITH TIME ZONE / TIMETZ, INTERVAL | **unsupported** | No approved time-only/duration tags; no conversion to timestamp/string |
| BIT / BITSTRING, BIGNUM / VARINT, GEOMETRY, VARIANT, extension/custom types | **unsupported** | Reject; do not install extensions or guess mappings |
| SQLNULL / NULL / UNKNOWN / ANY, unresolved literal/internal types | **unsupported as inferred schema** | Require a declared concrete schema. `missing` and `null` are value-state tags under that schema, not inference shortcuts |
| Any unlisted type/alias or unsupported nested child | **unsupported** | Stable `unsupported_logical_type`, no data echoed |

Descriptors include every field (≤500 at every dictionary level), not just visible columns; depth ≤16, total descriptor nodes ≤10,000. An approved sample needs ≤25 top-level committed fields even when some values are missing. Numeric logical values use exact strings on the seller-origin row representation where JSON numbers would lose precision; boolean/null remain native, missing properties remain absent, arrays/objects retain structure. Sender and viewer parser fixtures pin these representations and reject coercive alternatives.

Canonical rows are ordered `[field_name, value_tag, normalized_value]` triples; absent is `[name,"missing",null]`, explicit null is `[name,"null",null]`. A present value uses its declared tag. Nested object members use the same declared, ordered logical normalization; arrays preserve order and explicit null positions. Schema descriptors and logical record members sort by NFC UTF-8 field-name bytes. JCS object-property ordering is a separate serialization operation, not permission to reorder schema arrays. Normalize strings/keys before hashing; reject NFC collisions and unknown fields.

Compute `schema_digest = SHA256("aim-schema-v1\0" || J(descriptors))`; `base = SHA256("aim-row-v1\0" || schema_digest || "\0" || canonical_row_bytes)`. Sort all records by `(base digest bytes, canonical_row_bytes)`, assign duplicate ordinals 0..n−1 within equal canonical rows, then leaf `SHA256(0x00 || "aim-leaf-v1\0" || base || uint64_be(ordinal))`. Node is `SHA256(0x01 || left || right)` with RFC6962 largest-power-of-two split, never odd-node duplication. Leaf count is 1..2^63−1. Empty datasets cannot offer a commitment/sample under this contract.

**Serialization risk and release stop:** the backend metadata helper uses Python `json.dumps(sort_keys=True)` and accepts arbitrary Python integers (`BE:app/utils/dataset_commitment.py:76–108`). It is not evidence of general RFC8785 conformance for supplementary Unicode object keys or integers beyond exact ECMAScript representation. Port existing admitted bytes unchanged; add independent RFC8785 comparison cases, UTF-8 descriptor order cases, supplementary-plane keys and 2^53 boundaries. Reject candidates whose admitted serialization cannot agree byte-for-byte; never silently modify the backend/reference corpus. If T's permitted input domain cannot be represented without disagreement, return the exact conflicting fixture for a coordinated contract correction before producer acceptance. This is a known conformance gate, not discovery delegated to MP.

### Full dataset cost, bounded execution and progress

Implement external sorting rather than porting the reference's in-memory list builder for production. Let N be records and C the total canonical bytes: parsing/hashing is O(C), sort O(N log N) comparisons plus bounded external-merge I/O, tree build O(N), and M selected proofs O(M log N) from disk-indexed subtree hashes. Store ≤2N−1 node hashes (approximately 64N bytes before indexes), source/row offsets and canonical sort runs on seller-local disk. Do not promise a fixed runtime or infer full dataset size from compressed source size.

One commitment job per installation initially. Proposed default worker budget: 512 MiB incremental RSS, including a 128-MiB DuckDB limit, ≤64-MiB sort runs and ≤16-MiB serialized input batches; native allocation overhead is measured, not assumed controlled by DuckDB's limit. Use a separate worker process; the parent cancels on the budget ceiling, emits `resource_limit`, and never signs partial output. A canonical row over 8 MiB fails with `record_resource_limit` rather than allocating unbounded memory; this operational ceiling is not the public sample cap. Disk quota defaults to 20 GiB per job, with explicit seller-local adjustment for larger datasets, and a 1-GiB free-space reserve. Track actual canonical/spill bytes; stop before quota/free-space exhaustion. No arbitrary dataset row-count ceiling beyond the protocol/resource bounds.

Job-private temp directories mode 0700, files 0600/no broader than source access, no symlink traversal. Clean row-bearing runs on success, cancellation, failure and interrupted-job startup recovery. Final public package is retained only in the chosen seller publication location; local private build records hold identities/options/digests, not a second permanent full-dataset copy. Selection changes after cleanup may require rebuilding; state that in UI. Hold an immutable source snapshot/version across parse and selection; reject source changes rather than serving cached proofs.

Expose local progress phases `reading`, `sorting`, `building_tree`, `selecting`, `scanning`, `hosting`, `ready`, with counts/bytes/elapsed time, cancellation and coded failures. Never place rows or paths in platform telemetry. Acceptance measures 1M/10M generated records, wide/large values, duplicated rows, low memory/disk and interruption; demonstrate flat bounded worker memory and identical small-fixture roots. ### Header receipts: exact local capture

Public URL must be HTTPS, ≤2,048 characters, public DNS/address, with no userinfo/query/fragment; reject all non-global IPv4/IPv6 results, redirects and uncertain DNS admission.
